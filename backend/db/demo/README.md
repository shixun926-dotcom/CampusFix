## 三、执行方式

```bash
# 1) 首次初始化（全新库）
mysql --default-character-set=utf8mb4 -uroot -p < db/schema.sql
mysql --default-character-set=utf8mb4 -uroot -p < db/data.sql

# 2) 生成演示数据（可反复执行，自动清理上一轮演示数据）
mysql --default-character-set=utf8mb4 -uroot -p < db/demo/demo_seed.sql

# 3) 演示结束如需移除
mysql --default-character-set=utf8mb4 -uroot -p < db/demo/demo_cleanup.sql
```

Windows PowerShell 不支持 `<` 重定向，改用：

```powershell
cmd /c "mysql --default-character-set=utf8mb4 -uroot -p < db\demo\demo_seed.sql"
```

Docker 环境：

```bash
docker exec -i campusfix-mysql mysql --default-character-set=utf8mb4 -uroot -p"$MYSQL_ROOT_PASSWORD" campusfix < backend/db/demo/demo_seed.sql
```

## 四、数据留存与状态稳定性

演示数据**不会被系统自动删除**：项目没有清理业务数据的定时任务；`demo_cleanup.sql` 只在手动执行时删除。

但需注意以下会**改变状态**（非删除）的机制，它们决定了演示态能保持多久：

| 机制 | 触发条件 | 对演示数据的影响 | 当前处置 |
|---|---|---|---|
| 自动派单 | `PENDING` 且 `review_at`/`created_at` 超过 24h 且无人接单 | 3 张抢单池工单会在 24h 后被派给在办最少的维修工 | `review_at` 设为 1–3 小时前，演示期内不受影响 |
| 自动验收 | `PENDING_CONFIRM` 且超过 `confirm_deadline` | 2 张待确认单会被自动完成并扣报修人信誉分 | 截止时间设为 15–20 天后 |
| 状态滞留巡检 | 非终态停留超 7 天 | 仅推送站内通知，不改状态 | 无影响（日志插入后 `updated_at` 为当前时间） |
| 高频故障预警 | 每日 08:00 统计 | 仅写预警表，可能新增重复预警 | 已预置 1 条，重复项不影响演示 |

**结论**：正常演示（数天内）数据稳定；若隔较长时间再演示，**重跑 `demo_seed.sql` 即可秒级复原**（幂等）。

## 五、注意事项

1. **不要在生产环境保留演示账号**：`demo_*` 账号密码公开且不强制改密，上线前务必执行 `demo_cleanup.sql`。
2. **重跑 `data.sql` 会清空全部业务数据**（该脚本先 `DELETE` 再 `INSERT`，包括演示数据），之后需重新执行 `demo_seed.sql`。
3. 演示工单**未附现场照片**（避免失效图片链接与脏文件），演示时可现场上传；上传校验（数量/后缀/魔数/大小）仍正常生效。
4. 所有时间字段基于 `NOW()` 相对生成，脚本任意时间执行都呈现「最近发生」的效果。
5. 演示账号信誉分：`demo_stu` 91（超时未确认扣 10、按时评价加 1），`demo_rep` 90（投诉成立扣 10），配套 `sys_credit_log` 流水已写入。
